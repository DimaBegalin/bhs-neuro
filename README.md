# Нейропрофориентация BHS

Замер работы мозга ребёнка на визите и разбор с родителем. Ободок читается
напрямую по Bluetooth, профиль и отчёт считаются на ноутбуке менеджера,
карточка визита уходит в общее облако и видна только своему менеджеру.

## Как это устроено

Три части, каждая на своём месте:

- **Сайт** — вход, панель менеджера и тест для ребёнка. Общий для всех.
- **Программа на ноутбуке** — читает ободок, считает профиль, собирает отчёт.
  Своя у каждого менеджера, ставится один раз.
- **Облако** — хранит карточки визитов и отчёты. Общее, но каждый менеджер
  видит только свои: это обеспечивает база, а не страница.

Ободок подключён по Bluetooth к конкретному ноутбуку, поэтому тест проходят
на той машине, где стоит программа. Сайт при этом открывается с любого адреса.

## Порядок работы менеджера

1. Открыть сайт, войти по почте и паролю.
2. Попасть в свою панель: там визиты, отчёты и состояние оборудования.
3. Нажать «Начать новый тест», заполнить анкету ребёнка.
4. Надеть ободок, отдать ноутбук ребёнку. Тест около восьми минут.
5. Отчёт появляется в панели сам, через полминуты после финального экрана.

Установка программы на новый ноутбук: [МЕНЕДЖЕРУ.md](МЕНЕДЖЕРУ.md).
Ноутбук может быть MacBook ([УСТАНОВКА.md](УСТАНОВКА.md)) или Windows
([УСТАНОВКА-Windows.md](УСТАНОВКА-Windows.md)). На iPad программа не
работает: там нельзя держать фоновый процесс с доступом к Bluetooth.

## Разработка

```
./.venv/bin/python -m bridge.main        # мост к прибору
./.venv/bin/python -m bridge.main --fake # без прибора, генератор сигнала
./.venv/bin/python -m pytest tests/ -v   # тесты
./.venv/bin/python tools/build_site.py   # пересборка страниц сайта
./.venv/bin/python tools/make_package.py # коробка для менеджера
```

Страницы сайта собираются из `web/` в `public/`. Править надо исходники
в `web/`, иначе сборка затрёт изменения.

Устройство прибора и разобранный протокол: [docs/ЖЕЛЕЗО.md](docs/ЖЕЛЕЗО.md).

Прибор читается по-разному на разных системах. На macOS прямой Bluetooth
через CoreBluetooth (`bridge/ble_device.py`), мост подключается вторым
к потоку штатного приложения. На Windows библиотека производителя
(`bridge/device.py`, `--channel sdk`), она сама включает поток; запасной
прямой канал там через bleak (`bridge/bleak_device.py`). Разбор байтов общий:
`bridge/headband_protocol.py`. Выбор делает `bridge/main.py` по платформе.
