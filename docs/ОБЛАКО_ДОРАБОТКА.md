# Что доделать в облаке, чтобы менеджеры не мешались

Локальная часть готова: каждый ноутбук подписывает свои визиты кодом
рабочего места, имена визитов больше не сталкиваются. Осталось научить
облако показывать это полем, а не приставкой в идентификаторе.

Доступа к проекту Supabase и к репозиторию панели у меня нет, поэтому
ниже готовые куски: выполнить и вставить.

## Шаг 1. Колонки в базе

Выполнить [ОБЛАКО_ДОРАБОТКА.sql](ОБЛАКО_ДОРАБОТКА.sql) в Supabase,
раздел SQL Editor. Он добавляет `operator` и `operator_name`, ставит
индекс и проставляет менеджера уже загруженным визитам по приставке.

## Шаг 2. Разрешить запись в новые колонки

Анонимному ключу нужно право писать эти колонки, иначе выгрузка визита
начнёт падать. В том же SQL Editor:

```sql
grant insert (operator, operator_name) on neuro_cards to anon;
grant update (operator, operator_name) on neuro_cards to anon;
```

## Шаг 3. Включить отправку на ноутбуках

Пока колонок нет, мост их не шлёт: неизвестная колонка роняет всю
выгрузку визита. После шагов 1 и 2 снять защиту одной строкой в
`upload/cloud_push.py`:

```python
PUSH_OPERATOR = True   # колонки operator и operator_name заведены в облаке
```

## Шаг 4. Панель

В облачной функции `neuro-panel`, действие `list`, добавить поля
`operator` и `operator_name` в выборку. На странице панели —
выпадающий список менеджеров рядом с поиском по имени.

## Проверка

После шага 3 провести один визит и открыть панель: у карточки должен
стоять менеджер. До этого шага различать визиты можно по приставке
в идентификаторе — она есть уже сейчас.
