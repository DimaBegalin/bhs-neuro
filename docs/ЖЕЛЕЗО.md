# Железо: что проверить при первом подключении

Первое подключение состоялось 12.08.2026.

| что | ожидание | факт |
| --- | --- | --- |
| имя устройства | Headband | Headband |
| семейство в SDK | одно из семейств BrainBit | **LEHeadband** |
| серийный номер | | 822597 (второй прибор в комплекте не проверялся) |
| частота сигнала | 250 Гц | SensorSamplingFrequency.FrequencyHz250 |
| число каналов | 4 | 4 |
| имена полей отсчёта | T3, T4, O1, O2 | T3, T4, O1, O2 плюс PackNum и Marker |
| единицы сигнала | вольты, умножаем на 1e6 | не подтверждено, поток пока не снят |
| совмещённый режим сигнал и сопротивление | поддерживается | заявлен в списке команд |

Поддерживаемые команды прибора: StartSignal, StopSignal, StartResist, StopResist,
StartMEMS, StopMEMS, StartFPG, StopFPG, StartSignalAndResist, StopSignalAndResist,
Idle, PowerDown.

## Три грабли, которые стоили вечера

1. **Версия SDK.** В `pyneurosdk2` 1.0.12 нет семейства `LEHeadband`, поэтому
   прибор не находится вообще, сканер молча возвращает ноль устройств. Появилось
   в 1.0.15. Версия зафиксирована в `requirements.txt`, понижать нельзя.
2. **Частота приходит перечислением.** `sensor.sampling_frequency` отдаёт
   `SensorSamplingFrequency.FrequencyHz250`, а не число. Разбирается в
   `_frequency_to_hz`.
3. **Другой способ подписки.** У `HeadbandSensor` метод `set_signal_callbacks()`
   идёт без аргументов, а сам колбэк присваивается атрибутом
   `sensor.signalDataReceived`. У BrainBit колбэк передаётся в метод. Обёртка
   поддерживает оба варианта.

## Главное про подключение

Прибор требует сопряжения на уровне операционной системы. Без него SDK пишет
в лог `Error read characteristic: need pairing!`, а все команды отвечают
`Code 513 ERR_DATA_SEND`. Сопрячь можно только через системный интерфейс:
Системные настройки, Bluetooth, раздел «Устройства рядом», кнопка «Подключить».
`blueutil --pair` для этого не годится, он работает с классическим Bluetooth
и отвечает Page Timeout.

Порядок на новой машине:
1. Нажать кнопку на ободке, дождаться мигания.
2. Сопрячь через системные настройки, дождаться статуса «Подключено».
3. Закрыть штатное приложение Mind Tracker, оно держит устройство за собой.
4. Запускать мост.

Удерживание кнопки до частого мигания переводит прибор в режим сопряжения,
короткое нажатие только включает его.

## Профиль прибора по Bluetooth

Снят напрямую 12.08.2026 через bleak, когда стало ясно, что библиотека
производителя падает. Это запасной и, похоже, основной путь к данным.

Адрес на этом MacBook: `A9D88C1F-2BC4-066A-E707-C807B4F6A473`
(идентификатор CoreBluetooth, на другой машине будет другим).

**Сервис Device Information `0000180a`:**

| характеристика | значение |
| --- | --- |
| `2a24` модель | 80.6 |
| `2a25` серийный номер | 822597 |
| `2a26` прошивка | 4.8.10 |
| `2a27` версия железа | 1.0.0 |

**Рабочий сервис `7e400001-b534-f393-68a9-e50e24dcca95`** это вариант
Nordic UART Service, тот же протокол, что у BrainBit, только префикс `7e`
вместо `6e`:

| характеристика | права | назначение |
| --- | --- | --- |
| `7e400002` | read, notify | статус, первый байт это заряд батареи. Прочитано `44 00 2d 08`, то есть 68 процентов, сходится с показаниями SDK |
| `7e400003` | write | канал команд |
| `7e400004` | notify | поток данных |
| `7e400005` | notify | поток данных |
| `7e400007` | notify | поток данных |
| `7e400008` | notify | поток данных |

Плюс сервис `0000fe59` от Nordic Semiconductor, это загрузчик прошивки,
трогать его незачем.

**Формат пакета разобран** 12.08.2026 на живом приборе:

```
108 байт = 4 байта счётчика + 8 блоков по 13 байт
блок = 1 служебный байт + 4 значения по 3 байта little-endian со знаком
порядок каналов T3, T4, O1, O2
```

Счётчик в первых четырёх байтах растёт ровно на 8, то есть по числу отсчётов
в пакете. Частота сходится: 31,3 пакета в секунду умножить на 8 это 250 Гц.
Значения приходят сырыми отсчётами 24-битного АЦП со смещением около двух
миллионов, перевод в микровольты сидит в `bridge/ble_device.py`.

Раскладка найдена перебором по критерию гладкости: у настоящего ЭЭГ соседние
отсчёты одного канала близки, поэтому отношение разброса разностей к разбросу
значений меньше единицы. У верного варианта 0,78, у всех остальных выше 1,2.

**Команду старта подавать не нужно**, если прибор ведёт штатное приложение:
мы подключаемся вторым и читаем тот же поток. Это и есть рабочий режим.

**Грабля:** когда ободок сопряжён и подключён к системе, он перестаёт себя
рекламировать, поэтому сканер его не находит. Подключаться надо по адресу
напрямую. Но если он успел уснуть, не поможет и это, нужно нажать кнопку.

## Побочные каналы расшифрованы, 13.08.2026

- **Канал `7e400005`, 10 пакетов в секунду**: сопротивление электродов.
  Счётчик с шагом 1, затем четыре uint32 в омах, порядок O1, O2, T3, T4.
  На надетом ободке 20-80 кОм. Готовый материал для светофора контакта.
- **Канал `7e400008`, 12.5 пакетов в секунду**: оптический пульсовой датчик.
  Счётчик с шагом 8, затем восемь пар «3 нулевых байта + 3 байта значения»,
  итого 100 отсчётов волны в секунду. Пульс подтверждён спектром на живом
  человеке: медиана 90 уд/мин при доминирующей частоте 0.7-3 Гц с
  выраженностью выше 6. Никаких команд для запуска не нужно, канал стримится
  вместе с остальными. Разбор: `tools/side_decode.py`.
- Канал `7e400007` за все записи молчал.

## Экспорт штатного приложения и сверка слоёв, 13.08.2026

Приложение выгружает поминутный CSV со своими метриками (cognitive score,
focus, chill, stress, self-control, anger, relaxation index, concentration
index, fatigue score, alpha gravity, heart rate). Импортёр:
`analyzer/mind_csv.py`.

Сверка на одной и той же живой сессии (боевой прогон 13.08):

| пара | связь | вывод |
| --- | --- | --- |
| их heart rate и наш пульс из канала 08 | **0,96**, медианы 80 и 78 | канал пульса подтверждён их же экспортом |
| их focus и наша включённость | **+0,73** | меряем одно и то же открытой формулой |
| их stress и наше напряжение | **-0,70** | их «стресс» устроен иначе, знак противоположный |

Что видно по их сырым колонкам: relaxation index это абсолютная мощность
альфы, fatigue score в их экспорте практически равен relaxation index
(различие в доли единицы, похоже на артефакт их выгрузки), alpha gravity
лежит в 6,8-13,4 и по смыслу это центр тяжести альфа-полосы в герцах, тот же
метод, что наш расчёт личного пика. Их формулы закрыты, поэтому в трактовке
опираемся на свои открытые метрики, их слой держим как контрольный.

## Первый живой сигнал, 12.08.2026

Снята запись покоя с закрытыми глазами на надетом ободке, 75 секунд.

```
альфа-пик 9,2 Гц, выраженность 4,7 при пороге 1,5
```

Методика подтверждена на реальном человеке, а не только на синтетике.

**Что пришлось учесть.** Сухие электроды прибора дают сильный медленный дрейф:
размах после снятия постоянной составляющей доходит до 30 тысяч микровольт,
а дельта-диапазон в пятнадцать раз мощнее альфы. При стандартном срезе 1 Гц
этот дрейф искажает оценку фона 1/f и топит пик. Решение в `analyzer/main.py`:
для поиска альфа-пика режем низкие частоты на 5 Гц, для метрик по полосам
на 2 Гц, иначе потеряли бы тету.

Диапазон подгонки фона поднят до 6-30 Гц: если оставить его ниже среза
фильтра, детектор начинает находить ложный пик на чистом шуме. Это ловится
тестом `test_profile_degrades_gracefully_without_alpha`.

**Открытый вопрос к пилоту:** выраженность пика на сухих электродах держится
недалеко от порога 1,5, так что сам порог стоит перепроверить на первых
десяти детях и при необходимости подвинуть.

## Два режима работы моста

**Свой канал** (`--channel ble`, по умолчанию). Читаем прибор напрямую,
считаем всё сами: личный альфа-пик, ERD, карту когнитивной эффективности.
Даёт сырьё, значит и глубину разбора. Ограничение: поток сейчас включает
штатное приложение, своей команды запуска мы пока не нашли, прибор к моменту
поиска уснул.

**Зеркало** (`--mirror`). Показания берём с экрана штатного приложения
распознаванием, дорожку с метками времени режем по блокам теста и получаем
состояние ребёнка на каждом типе задач. Ребёнок при этом проходит тест у нас.
Это упрощённый путь: сигнал обрабатывает прибор, мы связываем его показания
с задачами.

Что теряется в зеркале: сырьё, а с ним личная частота альфа-пика и цена
усилия по десинхронизации. Остаётся связка «тип задачи и состояние», ради
которой всё и делалось.

Ограничения зеркала, обнаруженные на практике:
- окно приложения должно быть **видно на экране**: захват чужого окна по
  идентификатору требует разрешения на запись экрана, которого у процесса нет;
- при заблокированном или спящем экране снимок не делается вовсе,
  `screencapture` отвечает `could not create image from rect`;
- частота обновления упирается в распознавание, это примерно раз в секунду,
  для блоков по 70 секунд достаточно, для живого монитора грубовато.

Практический вывод: зеркало годится как быстрый старт воронки, свой канал
нужен для глубины и надёжности. Ближайшая задача для своего канала это найти
команду запуска потока в характеристике `7e400003`, скрипт
`tools/find_start_command.py` перебирает варианты сам.

## Закрытая проблема с библиотекой производителя

При старте потока сигнала нативная библиотека падает с segmentation fault.
Соединение при этом устанавливается штатно: имя, серийник, батарея и список
команд читаются. После падения прибор остаётся занятым, и следующая попытка
получает `Code 108. Sensor unsupported`, лечится выключением и включением ободка.

Что пробовать дальше: другие версии SDK (1.0.13, 1.0.14), запуск под Rosetta
на случай бага в arm64-сборке нативной библиотеки, `brainflow` как второй канал.

## Что проверить обязательно

1. Mind Tracker закрыт. Прибор держит одно подключение по Bluetooth,
   при запущенном штатном приложении наш мост устройство не увидит.
2. macOS спросит разрешение на Bluetooth для процесса Python. Выдать.
3. Размах сигнала после фильтров в десятках микровольт. Единицы означают,
   что единицы измерения другие, тогда правится VOLTS_TO_MICROVOLTS.
4. Контрольная запись покоя взрослого с закрытыми глазами на 60 секунд:
   альфа-пик должен найтись в диапазоне 8-12 Гц с выраженностью выше 1,5.
   Это главная проверка методики на реальном железе.
